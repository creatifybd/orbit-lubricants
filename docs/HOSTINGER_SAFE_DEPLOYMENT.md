# Orbit Lubricants — Hostinger Safe Deployment Procedure

**Status:** Procedure prepared; production website has NOT been updated under this plan.

## Why the site is stale
On 2026-10-20 the GitHub Actions FTPS deploy recorded a successful sync and the page check found generic JS assets. However, production still displayed an older 14-pack catalog while the repository contained 38 records. Such a check does not establish that FTPS was writing to the document root actually served by orbit-lubricants.com. Do **not** assume a specific Hostinger directory until the domain's actual mapping is verified.

## Preflight — required manual evidence
In hPanel, open **Websites → orbit-lubricants.com → Manage**. Capture redacted screenshots of:
1. Website > Details / File Manager, showing the **exact document root** serving the Orbit domain. The label and nesting may vary by hPanel version.
2. Files > FTP Accounts, showing the target **folder/directory mapping** for the Orbit FTP user. Redact username if sensitive, password, tokens, connection strings or IP tied to unrelated sites.
3. Advanced > Git (if configured), showing whether Hostinger is concurrently deploying the repository root to the same website. Do not delete or disconnect anything yet.
4. GitHub > Settings > Secrets and variables > Actions: only confirm whether `FTP_SERVER`, `FTP_USERNAME`, `FTP_PASSWORD` and `FTP_SERVER_DIR` are populated. **Never disclose their values**.

There may be multiple domains in one Hostinger account. All target changes must be scoped to Orbit's own document root. **Do not touch Joytun, CreatifyBD or any other domain.**

## Before changing production
- Record the current resolved site address, live HTML entrypoint and actual hashed JS bundle.
- Download a verified backup of Orbit's complete current document root and, where applicable, database/configuration (through hPanel's official backup workflow). Store the backup outside public_html and confirm its files can be opened.
- Identify the sole deployment strategy. Prefer verified FTPS deployment of `dist/` or a manually uploaded `dist/` artifact; **do not run both Hostinger Git-to-root and FTPS-to-dist on the same document root** without a tested integration.
- Validate approved product artwork: do not resize, recolor or edit original packaging assets.

## Deployment acceptance
1. Build only from reviewed branch/commit after verification (the branch PR is still DRAFT).
2. Read `dist/deployment.json` and note its exact `commit` and `productCount` **when generated by the release workflow**. A staging-only artifact may not include this marker.
3. Put `dist/` **contents**, not an extra nested `dist` directory, inside the verified Orbit document root. Do not clean-slate existing files without a tested rollback.
4. Confirm https://orbit-lubricants.com/deployment.json returns the expected commit and 38 product records. If it does not, stop and inspect the domain mapping/CDN cache; never claim success from a generic `/assets/` check.
5. Confirm 200 status, render and metadata for:
   - https://orbit-lubricants.com/
   - https://orbit-lubricants.com/products/
   - https://orbit-lubricants.com/products/nova-hd40-1l/
   - https://orbit-lubricants.com/contact/
   - https://orbit-lubricants.com/sitemap.xml
   - https://orbit-lubricants.com/robots.txt
   - one original product image, CSS and JS asset
6. Verify `www` vs apex redirect canonicalization, mobile, search/filter/compare, header/footer, form delivery and web analytics (only if actually configured).
7. Submit sitemap in already verified Google Search Console property after deploying and verifying canonical URLs.
8. If any critical check fails, restore the verified backup and record the error/logs before trying again.

## Public safety and privacy
- Publicly accessible `deployment.json` may contain only a commit SHA, catalog count, version and timestamp. Do not expose repository secrets or internal machine paths.
- Firebase, Firestore, central CMS, genuine server-side enquiry delivery, Google Analytics and consent controls need separate owner verification and cannot be inferred from frontend build success.
- Repeated GitHub Actions retries or automation that bypass GitHub limits are not permitted; run only the smallest needed CI checks and respect normal usage policies.

## Manual-support handoff
Ask the owner for **one screenshot at a time**:
1. Orbit domain's document-root path.
2. Matching FTP account's directory mapping.
3. Whether Hostinger Git deployment is active for Orbit.

Never ask the owner to send a password, token, private key, or Firebase service-account JSON in chat.
